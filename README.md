# OpenToConnect (O2C)

Windows-клиент защищённого подключения на базе [OpenConnect](https://www.infradead.org/openconnect/). Работает с протоколами, которые поддерживает OpenConnect: AnyConnect-совместимые серверы (в том числе ocserv), GlobalProtect, Pulse/Juniper, F5, Fortinet, Array.

*A Windows client for OpenConnect-compatible servers: a system service, a compact tray UI, per-PC split-tunnel exclusions (IPs, subnets, domains, `*.domain` masks, programs and folders). Documentation is in Russian.*

> **Оговорка.** OpenToConnect — независимый проект с открытым исходным кодом. Он не связан с Cisco, Palo Alto Networks, Juniper Networks, Ivanti (Pulse Secure), F5, Fortinet, Array Networks или авторами OpenConnect, и они его не поддерживают и не одобряют. Названия продуктов и протоколов упоминаются только для указания совместимости и принадлежат их владельцам.

## Возможности

- Подключение по логину и паролю; пароль хранится зашифрованным.
- Служба Windows: окно работает без прав администратора, подключение не рвётся при закрытии окна.
- Автоматическое переподключение при обрыве; при ошибке логина повторов нет, чтобы не заблокировать учётную запись.
- **Исключения из туннеля** на каждом ПК: IP-адреса, подсети, домены, маски `*.example.com`, программы и папки с программами. Применяются сразу, без переподключения.
- DNS этого компьютера по умолчанию или DNS сервера — на выбор.
- Компактное окно, значок в области уведомлений, светлая и тёмная тема по системе.
- Установка одним файлом MSI.

Требования: Windows 10 версии 2004 или новее (x64), Windows 11.

## Установка

1. Скачайте `OpenToConnect-<версия>.msi` со страницы [Releases](https://github.com/Kagaris44/O2C/releases).
2. Запустите файл и подтвердите запрос прав администратора.
3. После установки окно откроется само. Позже его можно открыть из меню «Пуск» или щелчком по значку в области уведомлений (рядом с часами).
4. Нажмите шестерёнку, укажите сервер, логин и пароль, нажмите «Сохранить». Вернитесь назад и нажмите большую круглую кнопку.

Если у сервера самоподписанный сертификат, при первом подключении окно покажет его отпечаток и кнопку «Доверять». Нажимайте её, только если отпечаток подтвердил администратор сервера.

Установщик пока не подписан цифровой подписью, поэтому Windows SmartScreen может показать предупреждение. Сверьте SHA-256 файла с указанным на странице релиза.

Новая версия ставится поверх старой тем же способом, настройки сохраняются. Удаление — через «Параметры → Приложения». Настройки и журналы в `C:\ProgramData\OpenToConnect` при удалении остаются.

## Окно

```
┌──────────────────────────────┐
│                          ⚙   │  настройки
│           ( ⏻ )              │  большая кнопка: подключить / отключить
│         Подключено           │
│    10.10.0.5 · 01:24:07      │  адрес и время в подключении
│ [Исключения]  Журнал         │
│ ┌────────────────────┐ + ⎘ ▣ │  добавить запись · вставить списком · программа
│ ● example.com          1  ✕  │  ● зелёная — действует, серая — ждёт, красная — ошибка
│ ● *.example.org        3  ✕  │  число — сколько маршрутов в обход туннеля
│ ● ▣ game.exe          12  ✕  │  программа: полный путь — в подсказке
└──────────────────────────────┘
```

- **Значок в области уведомлений** показывает состояние цветом: зелёный — подключено, жёлтый — подключение, красный — ошибка, серый — отключено. Щелчок открывает окно. Меню: «Подключить / Отключить», «Открыть», «Выход».
- **Крестик окна** прячет его в область уведомлений. «Выход» в меню значка закрывает окно и значок, а подключение остаётся (его держит служба).
- **При входе в Windows** значок запускается сам, без окна.
- **Исключения** добавляются по одной записи: ввести и нажать Enter или «+». Кнопка «вставить списком» добавляет все адреса из буфера обмена (по строкам, через запятую или пробел). Кнопка с окном программы предлагает выбрать «Программа (.exe)…» или «Папка с программами…». Удаление — крестик у записи. Подсказка у записи показывает маршруты или текст ошибки.
- **Журнал** — на отдельной вкладке. Шумные строки openconnect (например, «DTLS handshake failed: Resource temporarily unavailable») в окне не показываются, но остаются в файле `C:\ProgramData\OpenToConnect\logs\openconnect.log`.

## Исключения из туннеля

При подключении трафик идёт так, как задал сервер: весь через туннель (полный туннель) или только к его сетям. В списке исключений можно указать адреса, которые пойдут напрямую, через обычное подключение компьютера. Список свой на каждом ПК.

```
# По одной записи на строку, после # — комментарий
203.0.113.5            # IP-адрес
198.51.100.0/24        # подсеть
example.com            # домен
*.example.com          # маска: сам домен и все поддомены
2001:db8::/32          # IPv6
C:\Games\Foo\foo.exe   # программа
C:\Games\Bar\          # папка: все программы в ней и во вложенных папках
```

- Добавленная или удалённая запись применяется сразу. Исключения действуют, только пока есть подключение; при отключении служба снимает все свои маршруты.
- **Домены.** Адреса определяются через DNS при подключении, обновляются каждые 5 минут и при смене сети. Кроме того, служба следит за журналом DNS-клиента Windows: как только любое приложение разрешает имя из списка, маршрут на полученные адреса ставится сразу. Поэтому работают и сервисы на CDN с меняющимися адресами.
- **Маски `*.example.com`** охватывают сам домен и все поддомены (`www.example.com`, `a.b.example.com`, но не `notexample.com`). Адреса для масок берутся только из журнала DNS: маршрут появляется, когда приложение обращается к такому имени. Первое соединение может на долю секунды уйти в туннель; служба закроет его, и приложение переподключится напрямую.
- **Программы и папки.** Пока есть подключение и в списке есть программы, служба следит за событиями ядра Windows о сетевых соединениях (ETW, `Microsoft-Windows-Kernel-Network`). Когда программа из списка устанавливает TCP-соединение или отправляет UDP-пакет, служба запоминает адрес и ставит на него маршрут мимо туннеля — обычно в пределах долей секунды. Первое соединение может уйти в туннель; TCP служба закроет, и программа переподключится напрямую.
  - Адреса хранятся **7 дней** с последнего использования (`C:\ProgramData\OpenToConnect\app-addresses.json`). Пока программа запущена, срок её адресов продлевается раз в минуту. Поэтому при следующем подключении маршруты ставятся сразу, ещё до запуска программы.
  - Исключение действует **по адресу, а не по программе**: если другая программа обращается к тому же адресу, она тоже пойдёт мимо туннеля. Для игр и клиентов со своими серверами это обычно не важно, для браузера — важно: добавлять браузер целиком не стоит, лучше домены.
  - Путь к программе указывается полностью. Папка охватывает все программы в ней и во вложенных папках; весь диск указать нельзя.
- **Браузеры со своим защищённым DNS (DoH)** обходят DNS-клиент Windows: для них маски не сработают, а обычные домены продолжат работать через периодическое разрешение.
- **Приоритет.** Если сервер прислал более узкий маршрут, чем исключение (например, сервер — `10.1.0.0/16`, исключение — `10.0.0.0/8`), побеждает маршрут сервера.
- **Как работает.** Для каждой записи служба ставит маршрут через основной шлюз компьютера — тот, через который трафик шёл бы без туннеля. Шлюз выбирается среди реальных адаптеров (Ethernet, Wi-Fi); туннели других программ пропускаются, даже если у них меньше метрика.
- **Уже открытые соединения.** Соединение, открытое до добавления исключения, привязано к адресу туннеля, и Windows продолжает вести его через туннель. Поэтому при добавлении исключения служба закрывает такие TCP-соединения, и приложение открывает новые, уже напрямую. Для UDP (QUIC) это невозможно, но браузеры при обрыве переходят на TCP.
- Если служба завершилась аварийно, при следующем запуске она снимет оставшиеся маршруты (`C:\ProgramData\OpenToConnect\routes.json`).

Не держите одновременно подключёнными OpenToConnect и другой клиент к тому же серверу: каждый ставит свои маршруты и DNS, и трафик пойдёт непредсказуемо.

## DNS

По умолчанию имена разрешает **DNS этого компьютера** — серверы основного сетевого адаптера, как без подключения. Туннелю DNS не назначается. Если такой DNS-сервер оказался бы за туннелем (например, публичный DNS при полном туннеле), до него ставится прямой маршрут. Внутренние имена вашей сети (например, `*.corp.example`) и исключения разрешаются локально.

Галочка **«DNS сервера вместо DNS этого компьютера»** в настройках назначает туннелю DNS-серверы и домены поиска, которые прислал сервер. Запросы тогда идут через туннель. Включайте её, если нужные имена есть только в DNS за сервером. Изменение применяется при следующем подключении.

## Безопасность

- Права администратора нужны только при установке. Всё, что их требует (адаптер, маршруты, DNS), делает служба; окно работает с правами пользователя.
- Пароль хранится в `C:\ProgramData\OpenToConnect\settings.json`, зашифрованный DPAPI; папка доступна только SYSTEM и администраторам. В openconnect пароль передаётся через стандартный ввод и не виден в списке процессов.
- **Сохранённый пароль сбрасывается**, если в настройках изменились сервер, логин, протокол или отпечаток сертификата. Иначе другой пользователь компьютера мог бы направить сохранённый пароль на свой сервер.
- Окно и служба общаются через именованный канал `\\.\pipe\O2C.Control`. Доступ — только локальным вошедшим пользователям, из сети — запрещён. Перед отправкой пароля окно проверяет, что на том конце служба: сервер канала работает в сессии 0, владелец канала — SYSTEM или администраторы.
- Любой вошедший пользователь компьютера может подключать и отключать туннель и править список исключений. Если туннель — обязательное требование вашей организации, учтите это.
- Пока есть подключение и в исключениях есть программы, служба держит сеанс событий ядра `O2C-AppConnections` (ETW): она видит, какие программы компьютера к каким адресам подключаются, но запоминает только адреса программ из списка. Сеанс закрывается при отключении.
- Пока есть подключение и в исключениях есть домены, включён журнал DNS-клиента Windows (`Microsoft-Windows-DNS-Client/Operational`). В нём фиксируются DNS-запросы компьютера; читать журнал могут администраторы. После отключения служба выключает журнал, если включала его сама.
- Все загрузки при сборке (исходники OpenConnect, Wintun) проверяются по SHA-256.

О найденных уязвимостях пишите через [Security Advisories](https://github.com/Kagaris44/O2C/security/advisories/new) репозитория, а не в открытые Issues.

## Как устроено

```
OpenToConnect.exe (окно, права пользователя)
    │  именованный канал \\.\pipe\O2C.Control
    ▼
OpenToConnect.Service.exe (служба Windows «O2C», SYSTEM)
    ├─ настройки: C:\ProgramData\OpenToConnect\settings.json
    ├─ запускает openconnect\openconnect.exe
    │     └─ openconnect вызывает OpenToConnect.NetConfig.exe — настройка сети туннеля
    ├─ переподключает при обрыве (5 → 10 → 20 → 40 → 60 с)
    ├─ ставит маршруты-исключения через IP Helper API Windows
    └─ журналы: C:\ProgramData\OpenToConnect\logs\
```

| Что | Имя |
|---|---|
| Папка установки | `C:\Program Files\OpenToConnect` |
| Служба Windows | `O2C` (отображаемое имя «OpenToConnect») |
| Процессы | `OpenToConnect.exe`, `OpenToConnect.Service.exe`, `openconnect.exe` |
| Сетевой адаптер | `O2C` (Wintun) |
| Данные | `C:\ProgramData\OpenToConnect` |

**Настройка сети без скриптов.** На каждом этапе соединения openconnect запускает помощник `OpenToConnect.NetConfig.exe` вместо стандартного vpnc-script через Windows Script Host. Помощник обращается к Windows напрямую (IP Helper API):

- назначает адрес адаптеру `O2C`, задаёт MTU и метрику;
- ставит маршруты: при полном туннеле — `0.0.0.0/1` и `128.0.0.0/1` (они уже маршрута по умолчанию и побеждают его, не трогая его самого), для IPv6 — `2000::/3`; в split-режиме — сети, которые прислал сервер;
- направляет маршрут до сервера и исключения сервера через основной шлюз;
- настраивает DNS.

При отключении всё снимается; при повторной попытке соединения маршрут до сервера пересчитывается. Журнал помощника виден в окне с пометкой `[сеть]`. Если настроить сеть не удалось, служба разрывает подключение и показывает причину.

Если служба падает, Windows перезапускает её; если падает openconnect, его перезапускает служба. При остановке службы openconnect завершается вместе с ней.

## Сборка

Нужен .NET SDK 10.

```powershell
dotnet build
dotnet test
./build/publish.ps1 -NoInstaller    # только .NET-часть в artifacts/publish
```

Полный MSI собирает CI (GitHub Actions, workflow `build`), результат — в артефакте `OpenToConnect-msi`. Для локальной сборки MSI нужна папка с результатом `build-openconnect.sh`: `./build/publish.ps1 -OpenConnectDir <папка>`.

**openconnect.exe.** Готовых консольных сборок OpenConnect под Windows не публикуется, поэтому CI собирает 9.21 из исходного архива (SHA-256 проверяется) в MSYS2 UCRT64. Скрипт сборки:

- заменяет заголовок `sec_api/stdlib_s.h`, которого нет в новом MinGW, на `stdlib.h`;
- применяет патчи из `build/patches`: запуск помощника `.exe` напрямую, без `cscript.exe`, и создание нового адаптера Wintun, если в реестре осталась запись удалённого;
- записывает версии пакетов MSYS2 и копирует их лицензии (`PACKAGES.txt`, `licenses/`).

**Релиз** создаётся по тегу: поднять `<Version>` в `Directory.Build.props`, добавить раздел версии в «Историю изменений» (он станет текстом релиза), слить в `main` и отправить тег `vX.Y.Z`. CI проверит совпадение версии, соберёт MSI и опубликует релиз с SHA-256.

Установщик содержит сторонние компоненты под их собственными лицензиями: OpenConnect и библиотеки (LGPL и др.), Wintun, .NET, модули WiX. Список и условия — в [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md); полные тексты лицензий устанавливаются вместе с программой.

## Участие

Предложения и исправления — через Issues и Pull Requests.

- Ветка `main` защищена: изменения попадают в неё только через PR, и только когда CI (сборка и все тесты) прошёл.
- Сборки CI для PR от новых участников запускаются после одобрения владельцем репозитория.
- Dependabot раз в неделю предлагает обновления зависимостей в виде PR и сообщает об уязвимостях в них. Ничего не сливается автоматически. WiX остаётся на версии 5.x: начиная с WiX 6 действует другая лицензия.

## План

- Мониторинг скорости: текущая скорость приёма и отправки через туннель, график за минуту.
- Обратный режим для программ: через туннель идёт только выбранная программа.
- Обновление без запроса прав администратора.
- Защита от утечек при полном туннеле (блокировка трафика и DNS мимо туннеля).

Первая публичная версия.

- Подключение по логину и паролю к серверам, совместимым с OpenConnect; служба Windows, окно без прав администратора, автоматическое переподключение.
- Исключения из туннеля: IP-адреса, подсети, домены и маски `*.domain`, с адресами из журнала DNS-клиента Windows; применяются сразу.
- Настройка сети туннеля собственным помощником через IP Helper API, без Windows Script Host.
- DNS этого компьютера по умолчанию, DNS сервера — по выбору.
- Компактное окно, значок в области уведомлений, тема по системе, установка одним MSI.
- Сохранённый пароль сбрасывается при смене сервера, логина, протокола или отпечатка сертификата.
- Файл сторонних лицензий; версии и лицензии библиотек OpenConnect включаются в установщик.
